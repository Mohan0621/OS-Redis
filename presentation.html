04 / 12
Architecture

System Architecture

Five clean layers from raw TCP bytes to persisted data

Layer 1

TCP Server — RedisServer.java

Listens on port 6379. Accepts TCP connections. Spawns a RedisClientHandler thread per client.

Layer 2

RESP Protocol — RespParser / RespWriter

Decodes the Redis Serialization Protocol from raw bytes into command arrays. Encodes results back to bytes.

Layer 3

Command Router — CommandRouter.java

Maps each verb to a DataType partition. Enforces concurrency via a shared Semaphore (8 permits, fair).

Layer 4

Worker Pool — DataTypePartition / RedisWorkerPool

12 worker threads across 5 partitions. Each has its own BoundedTaskQueue — zero cross-type contention.

Layer 5

Database + Persistence — RedisDatabase / AofLogger

In-memory stores per data type. Every write is appended to redis.aof and replayed on startup.

Redis Serialization Protocol — a simple line-based format over TCP, human-readable and binary-safe

🔒 Semaphore Gate

Semaphore(8, fair) shared by all partitions. Caps total concurrent DB ops. Prevents thundering herd under spike load.

📦 BoundedTaskQueue

Each worker has a fixed-capacity blocking queue. Full queue throws TaskRejectedException — error sent to client. No unbounded memory growth.

🔑 Key Hashing

Within a partition, tasks are hashed by key. Same key always hits the same worker, preserving per-key ordering.

OS Concepts · Persistence

AOF Persistence

Every write command is appended to redis.aof in RESP format before the response is returned to the client.

  • Write path: Execute command → return result → append to AOF file
  • Read path: No file access — all reads come from RAM
  • Startup replay: Server reads AOF line by line and re-executes every command to rebuild in-memory state
  • Durability: Even after a crash, the AOF contains the full history of all writes
  • Lazy expiry: Keys with TTL are checked on access — expired keys are silently removed

What redis.aof looks like

*3\r\n$3\r\nSET\r\n$4\r\nname\r\n$5\r\nMohan\r\n *3\r\n$4\r\nHSET\r\n$6\r\nuser:1\r\n... *2\r\n$5\r\nINCR\r\n$7\r\ncounter\r\n *4\r\n$5\r\nLPUSH\r\n$6\r\nmylist\r\n...

⚠ Crash Recovery

If the server crashes mid-write, the last line may be a partial command. Replay skips it and continues — no data loss beyond the incomplete command.
